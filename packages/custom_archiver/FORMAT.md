# Формат архива `.hpa` (версия 1)

Все числа — little-endian. Данные пишутся и читаются потоком: архиватору не нужно держать файл целиком в памяти.

## Заголовок архива

| Поле    | Размер | Значение       |
|---------|--------|----------------|
| magic   | 4      | `HPA1` (ASCII) |
| version | 1      | `1`            |

## Запись (повторяется для каждого файла)

| Поле         | Размер | Значение                                 |
|--------------|--------|------------------------------------------|
| marker       | 1      | `0x01` — запись, `0x00` — конец архива   |
| pathLength   | 2      | длина пути в байтах UTF-8                |
| path         | N      | путь, см. «Пути записей»                 |
| originalSize | 8      | исходный размер файла                    |
| blocks       | ...    | последовательность блоков (см. ниже)     |
| crc32        | 4      | CRC-32 исходных данных файла             |

## Пути записей

Поле `path` — путь в кодировке UTF-8. Допустим только путь, который удовлетворяет всем правилам:

1. Путь относительный, единственный разделитель — `/`. Символ `\` запрещён целиком, чтобы на Windows он не стал вторым разделителем.
2. Путь не пустой: `pathLength` от `1` до `65535` байт.
3. Путь не абсолютный: не начинается с `/`, не начинается с буквы диска (`C:`, `c:` и т. п.), не является UNC-путём (`\\server\share`, `//server/share`).
4. Нет пустых сегментов: нельзя `//`, `/` в начале или в конце.
5. Нет сегментов `.` и `..`.
6. Нет NUL и других управляющих символов (U+0000–U+001F и U+007F).

Распаковщик обязан проверить путь **до** вызова `EntryTarget.create`. Если путь нарушает хотя бы одно правило, распаковка прекращается с `ArchiverException`, а `create` для этой записи не вызывается. Упаковщик проверяет пути источников по тем же правилам и не пишет запись с недопустимым путём. Проверка реализована в `ArchivePaths.validate`.

## Блок

Файл режется на блоки до 64 КиБ исходных данных, каждый сжимается независимо. Так распаковка идёт чанками, а ошибка в одном блоке не тянет за собой весь файл.

| Поле           | Размер | Значение                                        |
|----------------|--------|-------------------------------------------------|
| originalLength | 4      | размер исходных данных блока; `0` — конец файла |
| storedLength   | 4      | размер payload                                  |
| method         | 1      | `0` — без сжатия, `1` — LZ77 + Хаффман          |
| payload        | M      | данные блока                                    |

Если сжатие не уменьшило блок, он пишется методом `0`.

## Метод 0 (без сжатия)

`payload` — исходные байты блока как есть, `storedLength` равен `originalLength`. Таблиц Хаффмана нет. Если `storedLength` не равен `originalLength`, это ошибка формата.

## Метод 1 (LZ77 + Хаффман)

Каждый блок сжимается независимо: окно LZ77 не переходит через границу блока, таблицы Хаффмана свои у каждого блока.

### LZ77

- Окно 32 КиБ: смещение `offset` от `1` до `32768`.
- Длина совпадения `length` от `3` до `258`.
- Блок кодируется как последовательность элементов «литерал» (один байт) и «совпадение» (`length`, `offset`), после которой идёт символ конца блока (EOB).
- Совпадение означает: скопировать `length` байт, начиная с позиции `offset` байт назад от текущего конца уже распакованных данных блока. Копирование идёт побайтно, поэтому `length` может быть больше `offset` (перекрытие, например `offset = 1` повторяет последний байт). `offset` больше числа уже распакованных байт блока — ошибка формата.

### Алфавиты

В блоке два канонических дерева Хаффмана.

**LitLen**, 513 символов:

| Символ  | Значение                                  |
|---------|-------------------------------------------|
| 0–255   | литерал, байт со значением символа        |
| 256     | конец блока (EOB)                         |
| 257–512 | совпадение, `length = символ − 254` (257 → 3, 512 → 258) |

**Dist**, 16 символов (коды 0–15). Код задаёт базовое смещение и число дополнительных бит; `offset = base + extra`, где `extra` — беззнаковое целое из дополнительных бит, старший бит первым.

| Код | base  | Диапазон    | Доп. бит |
|-----|-------|-------------|----------|
| 0  | 1     | 1           | 0  |
| 1  | 2     | 2           | 0  |
| 2  | 3     | 3–4         | 1  |
| 3  | 5     | 5–8         | 2  |
| 4  | 9     | 9–16        | 3  |
| 5  | 17    | 17–32       | 4  |
| 6  | 33    | 33–64       | 5  |
| 7  | 65    | 65–128      | 6  |
| 8  | 129   | 129–256     | 7  |
| 9  | 257   | 257–512     | 8  |
| 10 | 513   | 513–1024    | 9  |
| 11 | 1025  | 1025–2048   | 10 |
| 12 | 2049  | 2049–4096   | 11 |
| 13 | 4097  | 4097–8192   | 12 |
| 14 | 8193  | 8193–16384  | 13 |
| 15 | 16385 | 16385–32768 | 14 |

Для кода `k ≥ 2`: `base = 2^(k−1) + 1`, дополнительных бит `k − 1`.

### Таблица длин кодов

Дерево из `N` символов хранится так:

| Поле    | Размер | Значение                                       |
|---------|--------|------------------------------------------------|
| count   | 2      | `N`, uint16 little-endian                      |
| lengths | N      | длина кода каждого символа по порядку: `0` — символ не используется, иначе `1`–`15` |

Для LitLen `N` обязан быть `513`, для Dist — `16`; другое значение или длина больше `15` — ошибка формата.

### Построение канонических кодов

По таблице длин коды строятся однозначно (тот же алгоритм, что в DEFLATE, RFC 1951, §3.2.2):

1. Берутся только символы с длиной `> 0`.
2. Они сортируются по длине по возрастанию, при равной длине — по номеру символа по возрастанию.
3. `code = 0`, `prevLength` = длина первого символа в этом порядке. Первому символу присваивается `code`.
4. Для каждого следующего символа: `code = (code + 1) << (length − prevLength)`, затем `prevLength = length`, символу присваивается `code` как `length`-битное число.

Ограничения (иначе ошибка формата):

- Сумма `2^(−length)` по используемым символам ровно `1` (полный префиксный код). Исключения: если используется ровно один символ, его длина `1` и код `0`; если в Dist не используется ни один символ, все длины `0` (в блоке нет совпадений).
- В LitLen символ `256` (EOB) обязан иметь длину `> 0`.

### Раскладка payload

```
LitLen table | Dist table | битовый поток
```

Битовый поток:

- Биты упаковываются в байты начиная со **старшего** бита каждого байта.
- Код Хаффмана пишется старшим битом первым (как он получен в алгоритме выше).
- Распаковщик читает символ LitLen:
  - `0–255` — дописывает литерал;
  - `257–512` — получает `length`, затем читает символ Dist, затем его дополнительные биты, получает `offset` и копирует `length` байт из окна;
  - `256` — конец блока.
- Встретить символ Dist без используемых символов в дереве Dist — ошибка формата.
- После EOB последний байт дополняется нулевыми битами. Ненулевые биты дополнения, лишние байты после EOB внутри `storedLength` или обрыв потока до EOB — ошибка формата.
- Число распакованных байт обязано совпасть с `originalLength` блока.
- Упаковщик обязан строить коды длиной не больше `15` бит.

## Ошибки

Неверный magic, неизвестная версия или метод, обрыв данных, несовпадение CRC-32 и недопустимый путь приводят к `ArchiverException` с описанием причины.
