# Формат архива `.hpa` (версия 1)

Все числа — little-endian. Данные пишутся и читаются потоком: архиватору не нужно держать файл целиком в памяти.

## Заголовок архива

| Поле    | Размер | Значение       |
|---------|--------|----------------|
| magic   | 4      | `HPA1` (ASCII) |
| version | 1      | `1`            |

## Запись (повторяется для каждого файла)

| Поле         | Размер | Значение                                 |
|--------------|--------|------------------------------------------|
| marker       | 1      | `0x01` — запись, `0x00` — конец архива   |
| pathLength   | 2      | длина пути в байтах UTF-8                |
| path         | N      | путь, см. «Пути записей»                 |
| originalSize | 8      | исходный размер файла                    |
| blocks       | ...    | последовательность блоков (см. ниже)     |
| crc32        | 4      | CRC-32 исходных данных файла             |

## Пути записей

Поле `path` — путь в кодировке UTF-8. Допустим только путь, который удовлетворяет всем правилам:

1. Путь относительный, единственный разделитель — `/`. Символ `\` запрещён целиком, чтобы на Windows он не стал вторым разделителем.
2. Путь не пустой: `pathLength` от `1` до `65535` байт.
3. Путь не абсолютный: не начинается с `/`, не начинается с буквы диска (`C:`, `c:` и т. п.), не является UNC-путём (`\\server\share`, `//server/share`).
4. Нет пустых сегментов: нельзя `//`, `/` в начале или в конце.
5. Нет сегментов `.` и `..`.
6. Нет NUL и других управляющих символов (U+0000–U+001F и U+007F).

Распаковщик обязан проверить путь **до** вызова `EntryTarget.create`. Если путь нарушает хотя бы одно правило, распаковка прекращается с `ArchiverException`, а `create` для этой записи не вызывается. Упаковщик проверяет пути источников по тем же правилам и не пишет запись с недопустимым путём. Проверка реализована в `ArchivePaths.validate`.

## Блок

Файл режется на блоки до 64 КиБ исходных данных, каждый сжимается независимо. Так распаковка идёт чанками, а ошибка в одном блоке не тянет за собой весь файл.

| Поле           | Размер | Значение                                        |
|----------------|--------|-------------------------------------------------|
| originalLength | 4      | размер исходных данных блока; `0` — конец файла |
| storedLength   | 4      | размер payload                                  |
| method         | 1      | `0` — без сжатия, `1` — LZ77 + Хаффман          |
| payload        | M      | данные блока                                    |

Если сжатие не уменьшило блок, он пишется методом `0`.

## Алгоритм (метод 1)

1. LZ77 со скользящим окном 32 КиБ: последовательность литералов и пар (длина, смещение).
2. Канонический код Хаффмана по частотам символов блока; таблица длин кодов хранится в начале payload.

## Ошибки

Неверный magic, неизвестная версия или метод, обрыв данных, несовпадение CRC-32 и недопустимый путь приводят к `ArchiverException` с описанием причины.
